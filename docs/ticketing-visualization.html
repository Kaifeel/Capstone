전체 구조

사용자는 API 서버로 접근하고, 핵심 데이터는 PostgreSQL에 저장합니다. Redis는 대기열과 입장 토큰을 관리하며, Prometheus와 Grafana는 운영 지표를 확인합니다.

Data / Infra

예매와 좌석 상태

좌석은 결제 전에는 HOLD 상태가 되고, 결제가 성공하면 RESERVED가 됩니다. 결제 실패나 시간 초과가 발생하면 다시 AVAILABLE로 복구됩니다.

AVAILABLE
→
HOLD
→
RESERVED
PENDING
→
CONFIRMED
또는
CANCELLED / EXPIRED
동시 요청이 같은 좌석에 몰려도 비관적 락 또는 낙관적 락으로 활성 예매는 1건만 남도록 검증합니다.
이전: 대기열 다음: 검증

부하 테스트와 모니터링

k6로 같은 좌석 집중 예매, 다중 좌석 예매, 대기열 흐름을 테스트하고 Prometheus/Grafana로 API와 인프라 지표를 확인합니다.

k6 동시 사용자 요청과 예매 성공/실패 흐름 확인
Prometheus Actuator, Redis exporter, Prometheus 자체 지표 수집
Grafana 요청량, p95 지연시간, 5xx 비율, Redis, JVM, DB 커넥션 확인
발표 핵심 문장: 대기열로 진입량을 조절하고, 락으로 좌석 정합성을 보장하며, 부하 테스트와 모니터링으로 결과를 검증했습니다.
